# へぇのタネ リリース実機テスト計画

最終更新日: 2026年7月14日
対象: Android、iPhone、iPad、Web
判定: 本計画の必須項目が完了するまで`release_blocked`

## 1. 目的

CIで確認できない実機・配布環境の挙動を確認し、次のリリースリスクを除去する。

- 初回起動、日替わり問題、回答、カード獲得の主要フロー不良
- 端末内保存、再起動、日付変更、リセット時のデータ不整合
- Android/iPhone/iPad/Webでの共有失敗
- 小型画面、大きな文字、キーボード、スクリーンリーダーでの操作不能
- 配布署名、Play内部テスト、TestFlight、Webホスティング固有の問題
- 予期しない権限要求、通信、クラッシュ、データ消失

## 2. 対象機能

- 初回オンボーディング
- 1日1問の日替わり四択クイズ
- 回答ロック、正誤、解説、カード獲得
- カード一覧、未獲得表示、カード詳細、出典リンク
- カード画像生成とOS共有
- 回答数、連続回答日数、カード閲覧数
- SharedPreferencesによる端末内保存
- テーマ設定
- データリセット
- 起動失敗、保存失敗、共有失敗時のエラー表示

対象外:

- アカウント、クラウド同期、広告、課金、通知、オンラインAI
- 開発者サーバーとの通信（現行実装には存在しない）

## 3. テスト対象成果物

各実施前に次を固定し、結果テンプレートへ記録する。

| Commit SHA | 40桁SHA |
| Version | `pubspec.yaml`のversionName/build number |
| Android | 配布署名済みAAB、Play内部テストから取得したAPK |
| iOS/iPadOS | App Store ConnectのBuild、TestFlight配布ビルド |
| Web | デプロイcommit、公開URL、ホスティング設定 |
| コンテンツ | questions/cards/manifestのハッシュまたはcommit |
| 実施日 | YYYY-MM-DD |
| 実施者 | 氏名またはGitHub ID |

CIの短期鍵で生成したRelease AABはコンパイル確認用であり、配布受入には使用しない。AndroidはPlay Consoleへ登録する正式な配布署名ビルドを対象とする。

## 6. テストデータ管理

日替わり問題はローカル日付で安定選択される。テスト結果には必ず次を記録する。

- 端末のローカル日付
- タイムゾーン
- 表示された問題IDまたは問題文
- 関連カードIDまたはカード名
- 回答前後の`totalPlayCount`、`streakDays`、所有カード数

正答・誤答の両経路を同一端末・同日で再現しにくい場合は、別端末、別ブラウザプロファイル、サイトデータ消去、アプリデータ消去を使用する。端末日付を変更した場合は、その事実を証跡へ明記し、通常日付での確認と区別する。

## 7. 共通テストケース

### INST-001 クリーンインストール

対象: Android / iPhone / iPad / Web

手順:

1. 旧アプリデータまたは対象サイトデータを削除する。
2. 正式な配布経路からインストールまたは公開URLへアクセスする。
3. アプリを起動する。

期待結果:

- 起動直後にクラッシュしない。
- 初回オンボーディングが表示される。
- 開発用ラベル、デバッグバナー、テスト用データが表示されない。
- 予期しない権限ダイアログが表示されない。

### ONB-001 オンボーディング完了

対象: 全プラットフォーム

手順:

1. 全ページの文章と画像を確認する。
2. 次へ進み、完了する。
3. ホーム画面へ遷移する。
4. アプリを終了し再起動する。

期待結果:

- 1日1問、カード収集、統計の説明が実装と一致する。
- ボタンや文章が欠けない。
- 完了後はホームへ遷移する。
- 再起動後にオンボーディングが再表示されない。

### HOME-001 初期ホーム表示

対象: 全プラットフォーム

期待結果:

- 今日の問題状態が表示される。
- 回答数、ストリーク、閲覧数、カード収集数が初期値と一致する。
- 画面にオーバーフロー、重なり、切れがない。

### QUIZ-001 正答フロー

対象: 全プラットフォーム

手順:

1. 今日の問題を開く。
2. 正しい選択肢を1回選ぶ。
3. 解説と関連カードを確認する。
4. ホームへ戻る。

期待結果:

- 選択後に回答がロックされる。
- 正答表示が問題データと一致する。
- 解説が表示される。
- 関連カードを獲得する。
- 回答数が1増える。
- 同じ操作を連打しても回答数・カードが重複しない。

### QUIZ-002 誤答フロー

対象: 全プラットフォーム

手順:

1. クリーン状態の別環境で今日の問題を開く。
2. 誤った選択肢を選ぶ。
3. 正答、解説、関連カードを確認する。

期待結果:

- 誤答であることと正答が明確に表示される。
- 誤答でも解説が表示される。
- 仕様どおり関連カードを獲得する。
- 回答数は1回だけ増える。

### QUIZ-003 同日再実行の冪等性

対象: 全プラットフォーム

手順:

1. 回答済み状態で問題画面を再度開く。
2. 戻る、再表示、再起動を行う。

期待結果:

- 同じ日・問題・カードの完了状態が復元される。
- 回答数、ストリーク、所有カードが重複加算されない。
- 別の問題またはカードを回答済みとして表示しない。

### SAVE-001 アプリ再起動後の保存復元

対象: Android / iPhone / iPad / Web

手順:

1. 問題へ回答する。
2. カード詳細を開く。
3. テーマを変更する。
4. アプリを完全終了またはブラウザを閉じる。
5. 再起動する。

期待結果:

- 回答済み状態、カード所有、統計、テーマが復元される。
- カード閲覧だけで回答数やストリークが増えない。
- 起動エラーへ遷移しない。

### SAVE-002 バックグラウンド・復帰

対象: Android / iPhone / iPad

手順:

1. 問題、カード詳細、設定の各画面でバックグラウンドへ移行する。
2. 数分後に復帰する。
3. 画面回転や別アプリ切替を行う。

期待結果:

- クラッシュしない。
- 選択前の問題が勝手に回答済みにならない。
- 回答後の保存状態が失われない。
- 共有処理中の復帰でも多重共有にならない。

### DAY-001 日付変更

対象: Android / iPhone / iPad / Web

手順:

1. 日付Dに回答する。
2. 保存状態を確認する。
3. テスト目的で端末日付をD+1へ変更する、または翌日に再確認する。
4. アプリを再起動する。

期待結果:

- 新しい日付の問題状態になる。
- 前日のカード所有と統計は保持される。
- 連続回答日数が仕様どおり更新される。
- 問題IDとカードIDの組が異なる場合、誤って回答済み表示しない。

注意: 手動日付変更の結果は、実時間経過による確認と区別する。

### COLL-001 カード一覧

対象: 全プラットフォーム

期待結果:

- 獲得済みと未獲得が視覚的・意味的に区別される。
- 未獲得カードの本文が表示されない。
- 所有カードIDが重複表示されない。

### CARD-001 カード詳細と統計

対象: Android / iPhone / iPad

### RESET-001 データリセット

対象: 全プラットフォーム

手順:

1. 回答、カード獲得、閲覧、テーマ変更を行う。
2. 設定画面からデータリセットを実行する。
3. 確認ダイアログのキャンセル経路を確認する。
4. 再度リセットし、確定する。

期待結果:

- キャンセル時はデータが残る。
- 確定時は回答、カード、統計、テーマ、オンボーディング完了が初期化される。
- 再起動後に古い保存更新が復活しない。
- リセット後はオンボーディングから開始する。

### OFFLINE-001 オフライン主要フロー

対象: 全プラットフォーム

手順:

1. 機内モードまたはネットワーク遮断にする。
2. 起動、オンボーディング、問題、回答、カード、設定を操作する。

期待結果:

- 主要フローが同梱データで動作する。
- 起動時にネットワーク待ちで停止しない。
- 出典リンクとオンライン共有を除き、通信必須表示が出ない。

### PRIV-001 権限と外部通信

対象: Android / iPhone / iPad

手順:

1. クリーンインストールから主要フローを実施する。
2. OS設定のアプリ権限を確認する。
3. 可能な場合は通信ログまたはプライバシーレポートを確認する。

期待結果:

- カメラ、写真、マイク、位置情報、連絡先、通知等の許可を要求しない。
- 通常利用で開発者管理サーバー、広告、分析、クラッシュ収集先への通信がない。
- 外部通信は、利用者が出典リンクまたは共有先を選んだ場合に限定される。

### UPGRADE-001 上書き更新

対象: Android / iPhone / iPad / Web
条件: 以前の配布可能ビルドが存在する場合は必須。存在しない場合はN/A理由を記録する。

手順:

1. 旧版で回答、カード獲得、テーマ変更を行う。
2. データを削除せず新版へ更新する。
3. 起動して保存データを確認する。

期待結果:

- インストールまたは更新に成功する。
- 保存JSONの移行に成功する。
- 回答、カード、統計、テーマが維持される。
- 起動エラーやデータ初期化が発生しない。

## 10. 異常系・安定性

- [ ] 主要ボタンを各20回程度繰り返してクラッシュしない
- [ ] 画面遷移を繰り返して著しいメモリ増加や操作遅延がない
- [ ] ストレージ空き容量が少ない環境で保存失敗を安全に表示する
- [ ] 共有先アプリがない、または共有を拒否した場合に復帰できる
- [ ] 外部ブラウザを無効化または通信遮断してもクラッシュしない
- [ ] アプリ強制終了直前の回答が、成功表示と保存状態で矛盾しない

保存データ破損や同梱JSON破損はRelease実機へ直接注入しにくいため、CI/自動テストの起動エラー検証を証跡として紐付ける。実機で再現可能なテストフックをReleaseへ残してはならない。

個人情報、Apple ID、Googleアカウント、通知内容、共有先の私的情報は証跡から除外する。

## 12. 欠陥管理

不合格ケースは`docs/testing/release-defect-template.md`を使用し、P0〜P3で分類する。

- P0: 公開停止。データ破壊、重大なセキュリティ/プライバシー問題、起動不能
- P1: 公開停止。主要フロー不能、再現性の高いクラッシュ、保存消失、重大な誤表示
- P2: 原則修正。回避可能な機能不良、特定端末の表示・共有問題
- P3: 改善候補。軽微な表示、文言、操作性

P0/P1は0件になるまで一般公開不可。P2を残す場合は影響範囲、回避策、公開判断を文書化する。
