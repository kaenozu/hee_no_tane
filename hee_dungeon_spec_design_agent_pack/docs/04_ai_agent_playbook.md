# 04. AIエージェント実装指示書

## 1. 目的

AIエージェントに、へぇダンジョンのMVPを段階的に実装させるための運用ルール。

## 2. 絶対方針

- v0.1では広告を実装しない
- v0.1では課金を実装しない
- v0.1ではサーバーを作らない
- v0.1ではログインを作らない
- v0.1ではアプリ内AI生成を実装しない
- まずゲームとして1プレイ完走できることを優先する
- UIは仮でもよいが、ロジックと保存は壊さない
- 変更後は必ず `flutter analyze` と `flutter test` を実行する

## 3. エージェントに渡す前提

```text
このアプリは、雑学クイズで敵を倒す1分クイズRPGです。
旧案「へぇの種」は、アプリ本体ではなく、ゲーム内の報酬・カード図鑑要素として統合します。
最初はAndroid向けFlutterアプリとして、オフライン、広告なし、課金なしで作ります。
```

## 4. 実装順序

### Phase 0: プロジェクト確認

- Flutterプロジェクトか確認
- 起動できるか確認
- テスト実行
- analyze実行
- 既存構成を壊さず方針を立てる

### Phase 1: 画面骨格

- ホーム
- ダンジョンマップ
- クイズバトル
- 解説
- リザルト
- 図鑑
- 設定

この段階ではデータは仮でよい。

### Phase 2: データモデル/JSON読み込み

- Question
- HeeCard
- Enemy
- SaveData
- Repository
- JSON parse test

### Phase 3: ゲームロジック

- 日替わり5問選択
- 正誤判定
- ダメージ計算
- 階層進行
- 勝敗判定

### Phase 4: 保存/図鑑

- ownedCardIds保存
- クリア報酬
- 図鑑表示
- データリセット

### Phase 5: 仕上げ

- 最低限の演出
- エラー表示
- テスト追加
- debug APKビルド

## 5. エージェントへの指示テンプレート

```text
docs/配下の仕様書と設計書に従って、へぇダンジョンMVPを実装してください。
今回はPhase Xだけを対象にしてください。
広告、課金、サーバー、ログイン、アプリ内AI生成は実装しないでください。
変更後に flutter analyze と flutter test を実行し、結果を報告してください。
大きな設計変更が必要な場合は、実装前に理由と代替案を説明してください。
```

## 6. 実装時の注意

### 6.1 既存コードを壊さない

- 大規模な一括書き換えを避ける
- 小さいPR単位で進める
- 画面とロジックを分離する

### 6.2 テスト優先

最低限、以下のテストを作る。

- 正誤判定
- ダメージ計算
- JSON parse
- 報酬選定

### 6.3 データ品質

- `verified: false` は出題しない
- sourceNoteのない問題は出題しない
- 選択肢は必ず4つ
- answerIndexは0〜3

### 6.4 UI品質

v0.1では見た目よりも完走を優先する。

最低限必要:

- 問題文が読める
- 選択肢が押せる
- HPが見える
- 正誤がわかる
- 図鑑が見える
